# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MMTVL is a personal, native macOS media launcher styled after tvOS. It runs full screen on a Mac mini (HDMI → AV receiver → TV) and is driven by a remote, keyboard/mouse, or phone. It launches external apps (Plex HTPC, Prime Video, a browser) and has built-in YouTube (TV UI) and IPTV experiences.

**Start every task by reading `docs/plans/MASTER_PLAN.md`.** It holds the goals, architecture decisions (D1…), and milestone status. Work is driven by per-milestone sub plans in `docs/plans/`.

## Planning workflow

- `/plan-milestone M<n>` (`.claude/skills/plan-milestone/`): research and write a detailed sub plan (`docs/plans/M<n>-<slug>.md`) from `docs/plans/TEMPLATE.md`, each step tagged with its role (`[implementer]`, `[designer]`, `[human]`, `[doc]`, plus `[security]`). Planning only, no app code. Best run with a strong model / high effort.
- `/build-plan docs/plans/M<n>-<slug>.md` (`.claude/skills/build-plan/`): the main session orchestrates and the subagents in `~/.claude/agents/` do the steps. `implementer` and `designer` write the code, `qa` checks every step, `security-reviewer` covers sensitive diffs and runs before a build for the MM (all Opus), and `release` runs `scripts/test-build.sh` / `scripts/deploy-mm.sh` and opens PRs (Sonnet), only after the user says yes. Subagents leave their work uncommitted; the main session commits each step. TV and MM checks are listed for the user, never claimed done.
- When implementing: follow the sub plan, tick its checkboxes, and keep the milestone status in the master plan current. Don't redesign. If the plan is wrong or ambiguous, record it under *Deviations & questions* in the sub plan and ask.
- Architecture-level changes must be reflected in the master plan's decisions table (§4).
- Completed sub plans live in `docs/plans/archive/`: when a milestone is `Done`, `git mv` its plan there and update its link in the master plan (§6). Only active and upcoming plans stay in `docs/plans/`.

## Project setup notes

- Xcode project with **file-system-synchronized groups**: any file placed under `MMTVL/` or `MMTVLTests/` is automatically part of that target. Don't add file references to `project.pbxproj` by hand. It only needs editing for build settings, new targets, or Swift package dependencies.
- No `Info.plist` file: it is generated from `INFOPLIST_KEY_*` build settings. Add Info.plist keys there.
- Swift 6 with **`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`**: types are main-actor by default. Mark pure models/helpers `nonisolated` when they must be used off the main actor.
- `NSLocalNetworkUsageDescription` (M7 L17, `INFOPLIST_KEY_NSLocalNetworkUsageDescription`; M7b: the text also mentions casting; M7j: and HDHomeRun tuners): outgoing connections to the Plex Media Server and HDHomeRun tuners (UDP broadcast discovery on 65001, HTTP) on the LAN, and the YouTube casting responder's multicast (receiving SSDP on UDP 1900, answering by unicast), need macOS's Local Network permission (System Settings → Privacy & Security → Local Network → MMTVL). Incoming phone remote and DIAL HTTP connections don't.
- Not sandboxed. **Hardened runtime** in both configurations (MR L3) with no runtime exceptions; the only entitlement is Apple Events (`AUTOMATION_APPLE_EVENTS`, for the power menu's Sleep/Restart through loginwindow), set by build settings, not an entitlements file. mpv's built-in Lua scripts are off (`MPVOptions.scriptsOff`), since LuaJIT can't run under the hardened runtime without the JIT exceptions. Debug builds are signed `Apple Development` with the team **H846CY8RB4** (no provisioning profile needed), so the Accessibility (TCC) grant for the global event tap and AX full screen survives rebuilds; releases are `Developer ID Application` (MR L2). Running a Developer ID build and a Debug build on the same Mac flips the Accessibility grant and Keychain access between them. To re-test onboarding: `tccutil reset Accessibility dev.mmtvl.launcher`.
- Deployment target: macOS 26.0. Bundle ID: `dev.mmtvl.launcher`.
- Version and build (M7c L28): `MARKETING_VERSION` is set by hand (1.1.0 from M7c, 1.2.0 from M7h, 1.3.0 from the first notarized release); `CURRENT_PROJECT_VERSION` goes up by 1 for **every build given to the user** (`scripts/test-build.sh` does it), so the installed build is always identifiable (Settings → About, and under the home clock). Never reuse or reset a build number.
- **Repository:** public at `github.com/dwolcot1/mmtvl` (MIT); the old history is the private archive `dwolcot1/mmtvl-private` (remote `private` in the maintainer's copy: never push its refs; they hold terms the public history was scrubbed of). Commits use the GitHub noreply address. **Release checklist:** bump `MARKETING_VERSION` (the build number is bumped by the script), commit on a clean `master` → `scripts/release.sh` → read the zip back (`stapler validate`, `spctl`, its SHA-256) → push, `git tag -a v<version>`, `gh release create v<version> <zip> --draft --notes-file …` (install lines, checksum, upgrade notes), publish after a check on the mini; run the gitleaks scans (`scripts/gitleaks.toml`) before any push to a public repo.
- Releases (MR): `scripts/release.sh` on a clean `master` bumps the build, archives, exports with Developer ID (`scripts/ExportOptions.plist`), checks every signature, the hardened runtime and the exact entitlement list, notarizes with the Keychain profile **`mmtvl-notary`** (`xcrun notarytool store-credentials`; it may be visible only from Terminal, not a Claude Code shell), staples, and zips to `build/release/MMTVL-<version>-build<N>.zip` with its SHA-256. It never tags, pushes or publishes. Notarization took 2 h 45 min the first time. A bumped number is spent even when the run fails. Dry runs off `master`: `MMTVL_RELEASE_ALLOW_BRANCH=1` (and `MMTVL_RELEASE_ALLOW_DIRTY=1`).
- Third-party licenses (MR): `Settings/ThirdPartyLicenses.swift` (Settings → Licenses, a QR code per component) and `Licenses/THIRD_PARTY_NOTICES.md` (bundled; full texts, the LGPL offer and relink steps). `ThirdPartyLicensesTests` fails when the app's frameworks and the list drift apart, e.g. after an MPVKit update: update both.
- Deploying to the Mac mini: `scripts/deploy-mm.sh` needs SSH key login to the host `mm` (Remote Login on the mini), an alias in `~/.ssh/config` that holds the mini's address, user name and your key (override with `MM_HOST`, `MM_KEY`). It stops MMTVL with SIGTERM (a quit request would ask for the kiosk lock's PIN), checks the signature and the build number, swaps the app in `/Applications` and opens it; the mini must be logged in. Only the last 3 builds' zips are kept, on the mini (`~/Downloads`, what `--rollback` installs; a build installed by hand is zipped there first) and on this Mac (`~/Desktop`); older ones are deleted. The dev Mac's `~/.ssh/config` has host `mm` for SSH debugging. The key has a passphrase, saved in the login Keychain; SSH from a Claude Code shell works only while macOS's launchd ssh-agent holds the key (`deploy-mm.sh` finds that agent itself when `SSH_AUTH_SOCK` isn't set). After a restart of the dev Mac, run `ssh-add --apple-load-keychain` in Terminal once (no passphrase asked). `deploy-mm.sh` retries the relaunch (`open` can fail with -600 right after the swap). Same signing team, so the Accessibility grant and Keychain items carry over.
- App icon: `Assets.xcassets/AppIcon` is the user's "tv" logo cropped square and masked to the macOS icon shape (824-point continuous rounded square with a soft shadow on a transparent 1024 canvas; macOS 27 shows it without the gray tile). `Assets.xcassets/Logo` is the same logo full-bleed (1024 × 1024, no rounded corners) for places that round it themselves (the phone remote's home-screen icon, M7b). Source: `~/Downloads/mactvlogo.jpeg` (2026-10-06), not in the repo.
- Tests use Swift Testing (`import Testing`, `@Test`, `#expect`), hosted in the app (`@testable import MMTVL`).
- Swift packages (M4): **MPVKit 1.0.0** (the LGPL `MPVKit` product only, never `MPVKit-GPL`; `import Libmpv`) and **GRDB 7.11.x**, linked to the **app target only**. Tests reach them through app types (`EPGStore.inMemory()`), never by importing them. `MMTVL.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` is committed. The first resolve downloads about 350 MB of MPVKit binaries. `MPVVideoView.swift` shows OpenGL deprecation warnings by design (D22). Multiview (M6) runs up to 5 mpv players, one per window, from a pool in `LiveTVModel` that is reused and never torn down.

## Conventions

- Logging: `os.Logger(subsystem: "dev.mmtvl.launcher", category: "<Component>")`.
- Secrets (IPTV URL/credentials, PINs) go in the Keychain via `App/Keychain.swift`: the **legacy login keychain**, service `dev.mmtvl.launcher` (never `kSecUseDataProtectionKeychain`, which fails with -34018 without a provisioning profile). The launcher PIN (D20) is account `launcher-pin`. Forgotten PIN, from the Mac: `security delete-generic-password -s dev.mmtvl.launcher -a launcher-pin`. The Live TV playlist URL is account `iptv-playlist-url`; the pasted guide URLs (M6b, up to 6, in priority order) are account **`iptv-guide-urls`**, a JSON array (M4's single `iptv-guide-url` is migrated on the next save and removed). All are pasted from the clipboard in Settings → Live TV. They carry account tokens: **never log or show a full IPTV source or stream URL**, only its host. Exception (M6b L2): Settings may show a guide's file name when it looks like a guide file (`.xml`, `.xml.gz`, `.gz`, at most 64 characters), never its query; logs still show the host only. Paired phones (M5) are account `phone-remote-phones`: a JSON array of names and token SHA-256 hashes (never the tokens). Reset from the Mac: `security delete-generic-password -s dev.mmtvl.launcher -a phone-remote-phones`. Plex (M7, D28) is account `plex-token` (the plex.tv user token, from Settings → Plex → Sign In at plex.tv/link) and account `plex-server-token` (the chosen server's access token); Settings → Plex → Sign Out removes both. From the Mac: `security delete-generic-password -s dev.mmtvl.launcher -a plex-token` and `… -a plex-server-token`. **Never log Plex tokens, link codes or full connection URIs** (server name and URI host only). Non-secret config is JSON in `~/Library/Application Support/MMTVL/`, read at launch. Missing files are written with defaults; a corrupt file is moved to `<name>.bak` and replaced with defaults:
  - `launch-items.json`: home screen tiles, in order. Per item, optional `launchFullScreen` (D15), `isHidden` and `requiresPIN` (D20; Settings and Exit to Desktop always ask when a PIN is set). Optional `artStyle` (M7 L24): `"icon"` for the app icon on a blurred backdrop; missing = designed art. Chromium web app tiles (PWAs, M7 L23) may have `startURL` (e.g. `"startURL": "https://meet.google.com/home?calling=1"`, set in Settings → Home Screen → the tile → Start Page): MMTVL then asks the browser to open the web app on that page; it must be on the app's own site.
  - `settings.json`: `globalInputEnabled`, `controllersEnabled`, `cursorAutoHide`, `launchAtLogin` (kiosk mode only). Optional hand-edited `youtubeUserAgent` overrides the YouTube TV user agent (D21). `phoneRemoteEnabled` (Settings → Remote & Input → Phone Remote). Hand-edited `phoneRemotePort` (default 8765, the page; the WebSocket uses port + 1; outside 1024…65534 falls back to 8765) and `phoneRemoteVolume` (`auto` | `receiver` | `tv` | `keys` | `system` | `app`, D25, D44; unknown values read as `auto`; despite the name it routes every volume button, the Siri Remote's and the volume keys too; `receiver` covers every connection, `tv` still needs `tvVolumeEnabled`, `keys` is SoundSource's until M7k removes it). `keyBindingsRevision` (M7 L7): which default bindings `key-bindings.json` has seen; a file without it is revision 1 and gets the Menu/Channel defaults added once at the next launch. `channelUpMovesUpList` (M7 L22, Settings → Remote & Input → Channel Up; default `true`: Channel Up zaps up the channel list like the Up arrow; `false`: to the higher channel number). `youtubeCastEnabled` (M7b, Settings → Casting; default `true`), `castDeviceID` (the DIAL device uuid, made once at launch; hand edits change how phones list MMTVL) and `reflectorAutoStart` (M7b, Settings → Casting → Android; default `true`). `kioskLock` (M7c D36, Settings → Restrictions → Keep Other Apps Out; default `true`) and `homeLivePreview` (M7c D37, Settings → Live TV → Preview on Home; default `true`). `showVersionOnHome` (M7c L28, Settings → About; default `true`): "Version 1.3.0 Build N" under the home clock. `homeStartTile` (M7c L32, Settings → Home Screen → a tile → Start Here; default `"plex"`): the tile focused at launch and after every Home press (a missing or hidden tile: the first tile); also set from the home tile menu's Start Here (M7m). `usePlaylistGuide` (M7f L4, Settings → Live TV → Guide Source; default `false`): use the guide the playlist's header names (`url-tvg`) instead of the pasted guides, which stay in the Keychain; the row shows only when the playlist names a guide and one is pasted. M7h: `siriRemoteEnabled` (D43, Settings → Remote & Input → Siri Remote → Use Siri Remote; default `true`, kiosk and `-windowed` alike) and `siriRemoteSwipes` (… → Swipes; default `false`: touches do nothing outside trackpad mode). The receiver (D44, Settings → Audio & TV → Receiver): `receiverBrand` (default `none`, no port is opened; `pioneer` (before 2016), `onkyo` (Onkyo/Integra/Pioneer 2016+), `denon` (Denon/Marantz), `yamaha`, `anthem`, `nad`; unknown values read as `none`), `receiverConnection` (default `serial`, `network` or `cec` (a receiver over HDMI-CEC; brand, port and address aren't used); unknown values read as `serial`), `receiverSerialPort` (a `/dev/cu.*` path; missing = the first USB serial port), `receiverHost` (the receiver's IP address or name; it must be, or resolve to, a LAN address), `receiverNetworkPort` (overrides the brand's control port; outside 1…65535 it's ignored) and `receiverMaxDB` (default `0`: the loudest MMTVL's volume buttons set the receiver, in dB; a value outside −100…30 reads as the default; brands that don't report dB and HDMI-CEC have no limit). The TV (Settings → Audio & TV → TV): `tvBrand` (default `none`, `panasonic` (a VIERA over the network) or `cec`; unknown values read as `none`), `tvHost` (its address or name, LAN only) and `tvMAC` (its wired MAC, for Wake-on-LAN); Find TV fills both in, and neither is ever committed or logged (the TV's host only). `tvVolumeEnabled` (… → TV → Volume Buttons Change TV Volume; default `false`): with no receiver set up, the volume buttons change the TV's own volume. `volumeToast` (Audio & TV → Show Volume; default `true`): off hides the volume and Muted toasts, never the ones that say why a press did nothing. `glassStyle` (M7l D46, Settings → System → Glass; `clear` (default) | `light` | `frosted` | `darkFrosted` | `solid`; unknown values read as `clear`): how see-through every glass panel and tile rim is; Reduce Transparency always gives Solid panels. `teamMatchInitials` and `teamMatchNicknames` (M7m L29, Settings → Live TV → My Teams → Matching; default `false`; see My Teams below). `antennaEnabled` (M7j, Settings → Live TV → Antenna → Use Antenna; default `true`; off: no discovery, no lineup, no antenna channels) and `antennaGuide` (… → Guide from SiliconDust; default `true`; off: MMTVL never calls SiliconDust and antenna channels use the pasted guides). Missing keys use defaults.
  - The **Settings screen** (the Settings tile, which is always on the home screen and can be moved but not hidden or removed) edits `settings.json`, `launch-items.json` and (Remote Buttons, M7) `key-bindings.json` live and saves each change at once. Hand edits made while MMTVL runs are overwritten by the next Settings change, so edit those files with MMTVL quit. Settings → System → Relaunch MMTVL picks up hand edits.
  - `iptv-state.json`: Live TV's last channel and group, `guideImports` (guide id = SHA-256 of its URL → last successful import; replaces M4's `lastGuideImport`/`lastGuideSourceHash`, which are ignored), and the Multiview snapshot `multiview` (layout, channel ids per window, highlighted window, whether Live TV was left in Multiview). An undecodable snapshot reads as none. `recentChannelIDs` (M7 L13): up to 10 channels watched, most recent first; the home screen's Live TV "On Now" shelf uses them when there are no favorites. `antennaGuideDue` (M7j): when the SiliconDust guide is next downloaded (20–28 h after a success, 1 h after a failure; missing = due); never a token. Hand edits are fine while MMTVL is quit.
  - `epg-overrides.json` (M4 L17): `{ "<channel name or tvg-id>": "<EPG channel id>" }` for channels the guide doesn't match by id or exact name. Keys match the playlist's channel name first, then its `tvg-id`, ignoring case. A value of `""` means no guide. Also written by Live TV's **Match Guide** (M6b: in the guide, Left on the programme airing now, Select, Match Guide), keyed by channel name; *Automatic* removes the channel's keys. Hand edits: Settings → Live TV → Refresh Now applies them (no relaunch); edit with MMTVL quit, since Match Guide rewrites the file. To find EPG ids: `gzip -dc guide.xml.gz | grep -o '<channel id="[^"]*"'`. Antenna channels (M7j L12) are keyed by their id, `"antenna:5.1"`, since tuner channel names repeat.
  - `iptv-channels.json` (M6b L5): `favorites` (channel ids, in order), `hiddenChannels` (channel ids), `hiddenGroups` (group names as in the playlist, or `"Antenna"`; antenna channel ids are `antenna:<GuideNumber>`, e.g. `"antenna:5.1"`, here and in `iptv-state.json`, M7j), and (M7f L13) `teams` (team ids, in the order added): pro from `IPTV/Teams/TeamCatalog.swift` (e.g. `"nba.lal"`), and (M7l D48) college, picked per sport, as `<league>.<ESPN slug>` with leagues `ncaaf` (FBS + FCS), `ncaam`, `ncaaw`, `ncaabase` (e.g. `"ncaaf.michigan-wolverines"`), from the bundled `IPTV/Teams/college-teams.json` (written by `scripts/gen-college-teams.py`; MMTVL never contacts ESPN; a missing or bad file means no college teams and a logged error). - **Antenna** (step 21, user choice U1): every path that step 4's probes should settle is built and behind a constant in **`source/lib/AntennaConfig.bs`**, each a decision with its reasons in `M12-decisions-log.md`: `discoverByBroadcast` (D21, on: SiliconDust's UDP 65001 broadcast), `discoverByName` (D22, on: `hdhomerun.local` when the broadcast finds nothing), `nameNeedsPeer` (D23, on: that answer counts only with a reported peer address), `playRawTS` (D24, on: the tuner's MPEG-TS straight to the `Video` node), `streamFormat` (D25, `""`: unset), `playMPEG2` (D26, on: MPEG-2 only where `CanDecodeVideo` says so, else hidden), `guideFormat` (D27, `"xmltv"`; `"json"` is untested and needs step 21's L-5 cap first), `guideHTTPGzip` (D28, off). A typed tuner address (Settings → Antenna → Address, private IPv4 only, D29) is tried after discovery. No channel scan on the Roku. Flip a switch only on device evidence, and record it.
- **Third-party code:** only `@rokucommunity/bslib` 0.1.1 (MIT) ships, as `source/bslib.brs`, which `bsc` adds to every build; its notice is `roku/licenses/bslib.txt` in each zip (log D61) and in `roku/README.md`. The test zip also holds the Rooibos framework (MIT). Everything else from npm is build tooling. Update the notice when bslib's version changes.

- **Never commit the provider's name, its domains or its Roku app's name** (D34; the public history was scrubbed of them): write "the provider" or `iptv.example`. The same goes for real playlist, guide or stream URLs, tokens, `DeviceAuth`s, LAN addresses and device serials; there is no private-terms file to grep with, so check `.pen` text and fixtures by eye.
- **BrighterScript naming trap:** inside a namespace, `bsc` silently resolves a name to that namespace's own function first, ignoring case. A local named like one of its functions (or like a namespace or a reserved word) is rewritten: a local `words` became `TeamMatcher.words` (step 17), and a namespace function `parseJSON` turned its own `ParseJson(text)` call into recursion (log D56). Pick distinct names, and **check the compiled `.brs`** in `out/staging/` when a value looks wrong.
- Other Roku facts the code depends on: Home can't be caught (Back never leaves, D49); the `Video` node never has focus (so `*` reaches the app); blocking the render thread for 3 s kills the app, so downloads and parsing run in Tasks; one `Video` plays at a time (no Multiview, Q30); HTTPS uses `common:/certs/ca-bundle.crt`; `roUrlTransfer`'s `EnableEncodings` stays off (a gzip body is bounded only by the app's own inflate).
